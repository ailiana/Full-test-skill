# UI 冒烟与浏览器验证

在需要实际操作网页、生成 UI 测试或定位页面流程问题时读取。只做用例设计时，可使用其中的检查范围，不要求建立浏览器环境。

## 选择当前环境可用的路径

先遵守宿主提供的浏览器、计算机操作和工具使用说明。不要猜测工具名称，也不要把某家产品专用命令当成所有客户端的前置条件。

1. 有可用的浏览器或应用控制工具时，用它验证实时页面和用户操作；适用的专用连接器优先。
2. 需要脚本化浏览器操作且已安装 Playwright CLI 时，使用该工具的实际帮助与当前能力。
3. 项目已有 Playwright 测试时，沿用其依赖、配置、测试命令和报告器；新增可重复的用例放进现有结构。

实时验证与项目测试可以组合：前者发现问题并核实视觉证据，后者保存稳定回归场景。按任务需要选择，无需为了跑一次冒烟替换项目框架。

如果没有浏览器工具或无法访问目标，仍可生成用例和脚本。对用户要求的实际执行标记 `BLOCKED`，写明缺少的能力；设计产物保持 `NOT_RUN`。

## 确定目标与范围

沿用用户明确指定的地址、环境、账号和本次变更范围。从仓库说明、现有启动脚本或运行中的服务补齐信息，避免重复询问。

- 先检查入口、关键路径、认证状态以及会影响预期的种子数据。
- 需要启动服务时使用项目已有命令，确认实际就绪信号，记录本轮启动的进程。
- 使用本轮授权范围内的环境和合成数据。对已授权的操作继续执行，不为每次点击重新确认。
- 新增依赖、真实业务写入或外部动作超出已有授权时，先完成不依赖该动作的检查，再说明需要的具体条件。

报告是默认产物。除非用户请求修复，不修改产品实现、自动更新快照或弱化断言来让测试变绿。

## 冒烟检查顺序

| 检查 | 可接受的证据 | 常见误判 |
|---|---|---|
| 页面可加载 | 实际页面状态、响应或明确错误 | 仅返回 HTTP 200 就判断可用 |
| 首屏有关键内容 | 检查实际渲染内容及相关截图 | 只确认一个空容器存在 |
| 主要控件可操作 | 点击、输入、提交后的观察 | 只确认按钮没有 disabled |
| 操作结果正确 | 可见状态变化与业务结果断言 | 点击命令无报错就算成功 |
| 运行时无相关错误 | 本次操作时段的 console / 页面错误 | 将历史日志全部当成新缺陷 |

选择与产品关键路径相关的检查，不把全站无边界爬取当作默认冒烟。无法登录时，认证后场景标为 `BLOCKED`，公共页面仍可继续验证。

## 每条用例的验证循环

1. 到达明确的起始页面与状态，并记录用例 ID。
2. 等待需要交互的内容可用，核对当前页面是否是预期页面。
3. 执行输入、选择、提交或导航等真实动作。
4. 断言可见结果；需要时核实刷新或重新查询后的状态。
5. 保存并检查关键证据，记录实际结果及 `PASS`、`FAIL` 或阻碍状态。

截图必须查看后才能支持视觉判断。用清楚的文件名和用例 ID 关联，例如 `screenshots/UI-001-submit.png`；截图中出现敏感内容时先裁剪或脱敏。

若输出只是静态示例、截图文件尚未查看或页面并未实际访问，把这些限制写进结果，不能据此宣称 UI 通过。

## 稳定地实现 Playwright 用例

优先使用用户能理解的角色、可访问名称或项目稳定的 `data-testid`。避免依赖 DOM 层级、自动生成的 class 和元素序号。

用定位器自动等待及明确状态断言处理异步变化。等待具体响应时限定请求路径与本次动作；不要用固定等待掩盖时序问题。

```typescript
import { test, expect } from '@playwright/test';

test('UI-001: 提交搜索后显示匹配结果', async ({ page }) => {
  // 测试数据与可访问名称应来自目标项目。
  await page.goto('/search');
  await page.getByRole('searchbox', { name: '搜索' }).fill('测试商品');
  await page.getByRole('button', { name: '搜索', exact: true }).click();
  await expect(page.getByTestId('search-results')).toContainText('测试商品');
});
```

此片段展示断言方式，不能原样套用到未知页面。先核实项目的路由、标签、定位器和种子数据，再生成实际用例。

认证状态应保存在项目忽略的本地路径。复用有效测试会话时检查角色与账号是否匹配；不提交 storage state、Cookie、Token 或截图中的凭据。

## 执行与报告器

优先运行受本次变更影响的用例或现有 smoke 标签。需要调整报告配置时合并现有配置，保留项目测试目录、设备、服务器和认证设置。

以下是可合并的配置片段，而非替换整个 `playwright.config.ts`：

```typescript
outputDir: 'qa-run/artifacts',
reporter: [
  ['html', { outputFolder: 'qa-run/playwright-html', open: 'never' }],
  ['json', { outputFile: 'qa-run/playwright-results.json' }],
  ['junit', { outputFile: 'qa-run/playwright-junit.xml' }],
],
use: {
  screenshot: 'only-on-failure',
  trace: 'retain-on-failure',
  video: 'retain-on-failure',
},
```

将片段内所有 `qa-run` 同时替换为本轮新建的运行目录，确保 JSON、截图、Trace 和视频位于同一目录树内，防止覆盖历史证据并便于统一导入。按项目命令运行后保存真实退出码；非零退出码不能因日志里出现部分通过就被忽略。

将 Playwright JSON 转入统一结果时，使用本 Skill 的 `scripts/import_playwright.py`，先通过 `--help` 查看实际参数，再用 `scripts/report.py` 合并报告。报告器不会替代浏览器执行。

## 失败、重试与回归

先分清断言失败与环境阻碍：依赖服务不可达、账号不可用、浏览器缺失属于阻碍；明确需求未满足属于失败。

在已授权范围内重建前置条件，保留原始错误及重试次数。通过重试的用例仍记录不稳定情况，不能只留下最后一次成功。

对于否定性验证，同时检查其对照场景，例如“错误输入不会提交”需要先证明有效输入能够触发提交，否则按钮根本不可用也会造成假通过。

用户要求修复时，在修复后重跑原始复现路径及必要的相邻正常路径；已有自动化基础时加入可稳定复现该问题的回归用例。没有运行过的部分继续保留未验证状态。

## 交付结果

交付本轮测试范围、目标环境、用例状态、命令退出码、缺陷复现步骤及证据路径。说明未执行场景与原因，不把页面评分等同于业务覆盖率。

仅结束本轮创建且已不需要的服务或浏览器会话。保留用户原有会话、其他测试任务和所有有用的结果文件。
