01 / 选择安装路径

Codex 客户端插件安装教程

以 Full Test 为例，先学会在客户端里点击设置、添加插件市场、安装并调用插件。普通用户无需命令行，也不需要 skill-installer。

按你的环境选一条路

你的情况推荐方法阅读
有 Codex 桌面客户端按按钮操作，填写 Git 来源第 2–4 页
习惯使用终端命令CLI 添加市场，再安装插件第 5 页
要分发本地或个人市场手工建立项目 / 个人清单第 6–7 页
只需要独立 Skill复制完整 Skill 文件夹第 8 页
先记住三个名称
Git 仓库：ailiana/Full-test-skill
市场名：ailiana-plugins　插件 / Skill 名：full-test

推荐从客户端开始

设置 → 插件 → 添加插件仓库 / 添加插件市场，填写来源后添加。然后在对应市场里安装 Full Test，打开新聊天，输入“使用 full-test 为当前项目生成测试用例”。

想安装其他插件时，换成作者提供的市场地址、分支和插件名即可；不是所有 Git 仓库都已经提供市场清单。

03 / 客户端操作

填写信息并安装 Full Test

先添加市场来源，再安装市场里的插件。以下值可直接用于 Full Test；安装其他插件时，以作者提供的信息为准。

2　按截图编号填写

编号与字段Full Test 填写内容
① 来源https://github.com/ailiana/Full-test-skill.git
② Git 引用main；本项目的主分支。其他仓库可按作者指定使用分支、标签或提交。
③ 稀疏路径留空，拉取完整仓库。plugins/codex 是占位示例。
④ 添加市场确认来源正确后点击，等待拉取和市场识别完成。
可直接复制到“来源”输入框
https://github.com/ailiana/Full-test-skill.git
稀疏路径的作用
稀疏路径用于只取仓库的一部分。Full Test 需要根目录清单和 skills 资源，所以此处保持空白。只有作者明确要求且仓库布局支持时，才填写指定路径。

3　添加成功后继续安装

返回插件列表或插件目录，选择 ailiana 插件市场，打开 Full Test 详情，点击“安装”或加号。看到已安装状态后，打开目标项目并新建聊天。

4　第一次调用：先确认工作流已经加载
使用 full-test，根据这份登录需求生成测试用例，先不执行。

部分插件需要额外连接账号或服务，按其说明操作；Full Test 本身不要求额外 AI API Key。安装失败先看第 4 页，详细使用与环境要求见第 9 页。

04 / 连接失败时

Git 拉取失败应该怎么处理

如果点击“添加市场”后出现 exit code 128、Connection was reset 或 SSL_read 错误，先检查网络与 Git 连接链路，再重试添加。

普通用户先检查这些项目

  1. 确认来源地址完整、没有复制进多余空格或反斜杠。
  2. 在浏览器打开该 GitHub 仓库，确认仓库存在且你有访问权限。
  3. 使用代理时，保持代理软件运行，确认当前节点能稳定访问 GitHub。浏览器可访问，不代表 Git 已使用相同代理。

不使用终端的备用方法

在 GitHub 选择 Code → Download ZIP，解压完整仓库。重新打开“添加插件市场”，把“来源”改为本地仓库根目录，例如 C:/Plugins/Full-test-skill；Git 引用和稀疏路径留空，再点击添加。

如何判断本地目录选对了
该目录下应直接存在 .agents/plugins/marketplace.json 和 plugin.json。不要选到解压文件夹的上一层，也不要只选 skills 子目录。本地来源的更新需重新同步源文件。

熟悉 Git 的读者可以检查代理

以下 socks5h://127.0.0.1:7892 仅是示例，使用前替换为你实际启用的协议、地址和端口。HTTP 代理应使用其对应的 http:// 地址。

先查看当前设置，再临时测试；不会因第二条命令永久修改代理
git config --global --get-urlmatch http.proxy https://github.com/ailiana/Full-test-skill.git
git -c "http.https://github.com/.proxy=socks5h://127.0.0.1:7892" ls-remote https://github.com/ailiana/Full-test-skill.git HEAD

临时测试成功、且需要长期使用该代理时，先记录已有配置，再保存只针对 GitHub 的设置：

仅在验证实际代理可用后执行；示例端口不是通用要求
git config --global "http.https://github.com/.proxy" "socks5h://127.0.0.1:7892"

保留 TLS 证书校验。代理节点仍不稳定时，切换可用节点或采用本地文件夹来源；一次测试通过不代表网络会持续稳定。

代理配置与 URL 匹配规则：Git 官方配置手册。

05 / 命令行备选

通过 CLI 添加市场和插件

在 PowerShell、终端或项目终端里运行这些命令。这里的 codex 命令不需要 skill-installer。

1　确认命令可用

终端命令
git --version
codex --version
codex plugin marketplace --help

若找不到 codex 或没有 plugin 子命令，使用第 2–4 页客户端方案，或第 8 页独立 Skill 方案。

2　添加市场，再安装 Full Test

终端命令
codex plugin marketplace add https://github.com/ailiana/Full-test-skill.git --ref main
codex plugin marketplace list --json
codex plugin list --available --json
codex plugin add full-test@ailiana-plugins
codex plugin list --json

第一条注册并跟踪 Git 市场。第四条才安装插件。最后一条检查结果：查找 name: full-test、installed: true 与 enabled: true。

你可以用 CLI 完成安装，也可只添加市场，再重启桌面客户端，从 Plugins / Plugins Directory 中选择该市场安装。菜单可能显示英文“Plugins”或中文“插件”。

不要把两种链接混用
marketplace add 接收的是含市场清单的仓库。本项目现已包含 .agents/plugins/marketplace.json；任意只有 plugin.json 的插件仓库，不一定能直接作为市场添加。

本机核实：Codex CLI 0.156.1 支持上述子命令；市场清单已被只读发现为 full-test@ailiana-plugins。教程制作没有替读者安装或启用个人插件。

06 / 项目市场进阶

手动添加项目插件市场

需要按项目分发插件或管理自定义本地清单时，可以使用这个方法；它不需要 codex 命令或 skill-installer。

1　下载完整仓库

打开 Full-test-skill 仓库，选择 Code → Download ZIP。解压后把插件内容放到业务项目的 plugins/full-test/。该目录下应直接看到 plugin.json 和 skills/。

2　建立市场清单

项目 .agents/plugins/marketplace.json
{
  "name": "project-testing",
  "interface": {"displayName": "项目测试插件"},
  "plugins": [{
    "name": "full-test",
    "source": {
      "source": "local",
      "path": "./plugins/full-test"
    },
    "policy": {"installation": "AVAILABLE", "authentication": "ON_INSTALL"},
    "category": "Productivity"
  }]
}

3　在客户端安装

用 Codex 打开该业务项目，按客户端提示信任你自己的项目；重启客户端。进入 Plugins Directory，选择“项目测试插件”，打开 Full Test，点加号安装，再新建聊天使用。

已有清单时合并
保留原来的顶层市场名与已有 plugins 条目，仅追加 Full Test 条目；不要覆盖别人的市场或插件。source.path 从项目根解析，不能按 .agents/plugins/ 目录解析。

07 / 自建市场

用 Git 链接维护个人市场

当插件仓库本身没有市场清单，或你想把多个仓库归入同一个市场时，可以手工维护个人 marketplace.json。

1　新建或合并个人清单

位置：~/.agents/plugins/marketplace.json。Windows 中 ~ 表示你的用户主目录，例如 C:/Users/你的用户名/。以下仅在该清单不存在时整份使用；已有清单时只合并条目。

个人 ~/.agents/plugins/marketplace.json
{
  "name": "my-testing",
  "interface": {"displayName": "我的测试插件"},
  "plugins": [{
    "name": "full-test",
    "source": {
      "source": "url",
      "url": "https://github.com/ailiana/Full-test-skill.git",
      "ref": "main"
    },
    "policy": {"installation": "AVAILABLE", "authentication": "ON_INSTALL"},
    "category": "Productivity"
  }]
}

2　重启并检查

重启客户端，在插件目录选择“我的测试插件”并安装 Full Test。私有仓库需通过 GitHub 正常授权；公开仓库一般无需账号。

插件在子目录里怎么办

将源类型改成 git-subdir，增加插件目录路径，例如：

仅替换 source 对象；owner/repository 是通用示例
"source": {"source": "git-subdir",
  "url": "https://github.com/owner/repository.git",
  "path": "./plugins/my-plugin", "ref": "main"
}

08 / 没有 skill-installer

直接安装完整 Skill 文件夹

只想使用 Full Test 工作流时，可绕过插件市场，手动复制仓库中的 skills/full-test。这个方法安装的是独立 Skill。

Windows PowerShell 示例

先进入你的业务项目目录；命令将仓库克隆到 vendor/Full-test-skill，再复制 Skill。

Windows PowerShell；首次安装，目标 full-test 目录应不存在
git clone https://github.com/ailiana/Full-test-skill.git vendor/Full-test-skill
New-Item -ItemType Directory -Force .agents/skills | Out-Null
Copy-Item -LiteralPath vendor/Full-test-skill/skills/full-test -Destination .agents/skills/full-test -Recurse

macOS / Linux 终端示例

macOS / Linux；首次安装，目标 full-test 目录应不存在
git clone https://github.com/ailiana/Full-test-skill.git vendor/Full-test-skill
mkdir -p .agents/skills
cp -R vendor/Full-test-skill/skills/full-test .agents/skills/full-test

没有 Git 时，使用 GitHub 的 Download ZIP，按同样目录结构用文件管理器复制。全局使用可将目标改成 ~/.agents/skills/full-test/；项目安装仅在该项目中生效。

选一种安装方式即可
已装插件时通常不用再复制同名 Skill。手动复制不会注册插件或 MCP，更新后要重新同步。已有目标目录时先确认备份与更新方式，避免重复套目录。

09 / 安装后使用

确认生效并运行第一次测试

安装后从目标项目新建聊天。先用“只生成用例”的请求确认 Skill 已加载，再接入真实测试环境。

确认插件与 Skill 可用

桌面端在插件目录的 Installed 区域检查 Full Test 已安装、启用。可输入 @ 选择插件/Skill；在 Codex 的 Skill 选择器中使用 $full-test。也可直接说“使用 full-test”。

第一次验证：不依赖浏览器或测试账号
使用 full-test，根据这份登录 PRD 生成测试用例。
覆盖正常、边界、异常和权限；先不执行。

给出测试范围与目标

执行示例：替换成真实环境与已授权范围
使用 full-test，测试当前项目的 staging 环境。
UI 冒烟覆盖登录、搜索、退出；接口依据 openapi.yaml。
凭据从环境变量读取。只测试并报告，生成 HTML 和 Markdown，
列出通过、失败、阻塞与未执行项。

仅生成用例不需要 Python 或浏览器。使用内置 API 执行/报告脚本需要 Python 3.10+；UI 实操需要会话可用的浏览器工具或项目 Playwright。安装 Skill 不会自动创建这些工具。

读报告时看这三个地方
① 范围与目标是否正确　② 是否存在 BLOCKED / NOT_RUN / SKIPPED 或 flaky　③ 失败是否有实际观测与复现证据。工具不足时报告不完整，不把未执行算通过。

让 Codex 给出报告的本地路径并在客户端打开。分享时连同 evidence/ 附件目录一起保存；测试报告不会自动上传给他人。

10 / 更新和排障

维护市场与解决常见问题

先判断卡在“市场未添加”“插件未安装”“旧聊天未刷新”还是“执行工具缺失”，再处理相应环节。

常用管理命令

最后两条分别卸载插件、移除市场；按需执行
codex plugin marketplace list --json
codex plugin list --available --json
codex plugin marketplace upgrade ailiana-plugins
codex plugin list --json
codex plugin remove full-test@ailiana-plugins
codex plugin marketplace remove ailiana-plugins

marketplace upgrade 用于刷新 Git 市场。刷新后重启客户端，在插件页检查更新/重新安装是否需要执行。手动复制的本地插件先更新其源目录；手动 Skill 则重新同步文件，二者不会因市场刷新自动改写。

现象优先检查
没有 skill-installer按第 2–3 页在客户端安装，或第 8 页直接复制 Skill。
codex 命令找不到使用第 2–4 页客户端方案；无需为此安装 CLI。
Git 链接不能添加市场连接报错看第 4 页；仓库缺市场清单时用第 7 页 Git URL 引用。
已看到市场但不能调用还需安装并启用插件，再开新聊天；加市场不等于装插件。
插件目录为空检查 JSON、路径根、项目已打开且可信，以及工作区安装策略。
找不到 SKILL.mdZIP 是否多套一层？应该是 full-test/SKILL.md，保留同目录资源。
改了源码但没有生效客户端使用安装后的缓存副本；刷新来源、重启并检查安装状态。
能生成用例，不能点网页检查浏览器工具、Playwright、目标网络和身份；独立 Skill 不自带执行环境。
命令体系不要混用
本教程使用 Codex 的 codex plugin marketplace add。Claude Code 的 /plugin marketplace add 不是这里的终端命令。Codex CLI 交互界面的 /plugins 用来打开插件浏览器。

11 / 速查与依据

把四个目录记清楚

Git 链接决定下载来源，清单决定市场展示，安装状态决定能否加载，聊天中的任务范围决定插件实际做什么。

文件 / 目录用途
插件根/plugin.json标准插件身份与元信息。
插件根/.codex-plugin/plugin.json兼容清单；Full Test 同时提供。
项目根/.agents/plugins/marketplace.json项目市场；本地 source.path 从项目根解析。
~/.agents/plugins/marketplace.json个人市场；本地 source.path 从用户主目录解析。
项目根/.agents/skills/full-test/仅给当前项目使用的独立 Skill。
~/.agents/skills/full-test/个人独立 Skill，适用于多个项目。

交付前自己核对

□ Git 仓库地址与实际清单匹配。

□ 安装的是 full-test@ailiana-plugins，名称来自市场清单。

□ 完整文件夹内有 SKILL.md、scripts、references、assets。

□ 已重启或新建聊天，Full Test 可被选择。

□ 第一次请求只生成用例；随后按真实目标和权限执行。

□ 报告保留阻塞、未执行与证据，不把演示结果当业务结果。
